## Shell concepts encountered

- `set -euo pipefail`: fail fast on errors, unset variables, and broken pipelines. This catches mistakes that would silently pass in a .NET app.
- Subshell `(cd "$dir" && pwd)`: changing directory inside `$(...)` avoids mutating the caller's working directory. Had to do this twice (basename + absolute path).
- Command substitution `$(...)` vs pipes: substitution captures output into a variable; pipes stream it to another process. Used both deliberately.
- `git -C <dir>`: run git against a directory without `cd`. Much safer for a tool.
- Exit codes: 0 success, 1 runtime error, 2 usage error. Verified with `printf 'exit code: %d' $?`.
- stderr vs stdout: error messages go to `>&2` so they don't pollute piped output. First evidence capture missed them - had to re-run with `2>&1`.
- `wc -l` on `git status --porcelain` to count changes; `cut -f1` on `du -sh` to strip the path.

## Stuck points / lookups

- Whether `return` inside `case` inside `main` propagates the exit code through `set -e` - it does (script exits with that code).
- Whether to use `sed` or `awk` for the extension histogram - used both: sed to extract the extension, awk to format the final columns.
- `shellcheck` is not installed - should install it next session for linting Bash.

## Known limitations (v0.1)

- Files without an extension are only counted, not listed.
- `.git` is excluded but other VCS dirs (`.hg`, `.svn`) are not.
- `info` on huge trees (e.g. `/tmp`) is slow because `find` is run twice.
- Last extension only (`file.tar.gz` counts as `gz`).
